# 状态路由 v3：全量错误模式与改进方向

分析对象是完整的 3035 条 OVO 预测。主要配对基线为原 progressive visual fill，两者保留相同的视觉 memory writer、Recent16 采样和最终答题提示词。官方 Recent16 作为补充参照，其采样相位、提示词和特征路径不同，不作为纯读取策略消融。

## 结论

本轮改进范围是：**固定同一个视觉历史库，让模型根据问题自动决定读取多少历史**，使 RT 整体少读历史，同时减少 BT/FT 被错误分配零历史的情况。新版确实让 RT 受益，但累计计数的提前停止抵消了收益。当前结果没有证明 RT 已不受损，也没有支持简单提高 Response 概率阈值。

用户已明确排除本轮修改存储容量或淘汰策略。下文存储审计保留为背景观察，不作为此次改进目标。问题条件化预算路由目前只是拟议方案，尚未实现或进行实验；已有代码仍为 native_response_prefix_v3。

| 范围 | 原 fill 错→v3 对 | 原 fill 对→v3 错 | 原 fill 与 v3 均错 | 官方任务宏平均变化（百分点） |
|---|---:|---:|---:|---:|
| BT | 6 | 10 | 146 | -0.3359 |
| RT | 22 | 5 | 156 | +1.7041 |
| FT | 14 | 63 | 616 | -2.2594 |
| 全部 | 42 | 78 | 918 | -0.2971（总分） |

总分为三个任务类别中子任务准确率均值的平均。逐样本正确数为 2075→2039，micro 准确率下降 1.1862 个百分点，不能与总分变化混用。FT 退化主要集中在 REC 累计计数（11 个收益、59 个损失），CRR 是 +3/-2，SSR 是 +0/-2；不能概括为所有“未来”相关能力都退化。

## 1. 首要新增错误：未覆盖过去，却确信可以回答总数

78 条退化中，73 条在仅用 Recent16 时触发 Response。REC 的 59 条退化中：

- 58 条 Recent16 就停止；58 条答案小于标准计数，1 条大于标准计数。
- 全部没有 memory eviction，说明这批历史还在缓存中，问题不是存储容量不足。
- 25 条的末轮 P(Response) >= 0.9，不能归因于只有低置信度的边界判断。

例如 `ovo-2353` 问总共多少次向镜头展示物品：标准 3，fill 为 3，v3 为 2；v3 仅看约 8.98–23.98 秒，P(Response)=0.964。`ovo-2354` 同类问题标准 4，fill 为 4，v3 仍为 2，仅看约 18.97–33.97 秒。这里引用的是保存的题目、标注、预测和时间戳；本次没有逐帧人工标注动作时间。

BT 也有相同的早停风险：`ovo-0598` 问喝水前如何处理袋子，fill 读取 24 帧历史后答对，v3 Recent16 阶段 P(Response)=0.620 后停下并答错。RT 同样存在少读历史反而答错的 5 条，因此不应把某个评测类别固定绑定为零历史。

## 2. 原生状态信号没有实现所需的充分性判断

6382 次探测只有 Response=1992、Silence=4390，没有 Standby 或非法状态。结束在 Response 的 1992 题答对 1305；结束在 Silence 的 1043 题仍答对 734。两组任务构成不同，这不是一个可直接比较的校准实验，但表明 Silence 不能解释为“无法正确回答”。计数题的 Response 样本尤其明显：578 条中仅 166 条答对。

在 Recent16 首轮 Response 且 fill 确有历史的 1310 条可配对子集上，fill 能挽回 73 题、也会损害 31 题。用固定 0.90 阈值将低于阈值的已保存 recent 答案替换为已保存 fill 答案，会使 85.7% 样本转回 fill、净增 17 个正确，但 RT 少对 13 题；0.95 则有 98.5% 转回 fill。这只是已有两个端点的事后替换统计，不等于运行修改后分阶段 controller 的结果，更不是经过验证的部署阈值。

因此，Response 适合作为候选作答信号，不能单独决定是否停止补充证据。题目所需的时间范围、事件完整性和未读历史是否可能改变答案，需要单独判断。

## 3. 长视频历史存在与路由无关的存储问题

v3 和 fill 的 bank 统计在全部 3035 条上相同；fill 每条都读取全部现存 bank，所以可以用它的时间戳检查可用历史范围。

- 1216 条发生过最老帧淘汰。
- 581 条在任何第二次年龄驱动池化发生前就开始淘汰，包含 274 条 EPM。
- 当前历史预算 16384 token，下一次压缩间隔 60 秒。每帧初次池化后占 690/510/391/1200 token 时，只能存 23/32/41/13 帧，在 1 fps 下不足以等到下一次压缩。此时 progressive pool 会变成短 FIFO。

例如 `ovo-0000` 截止 215 秒，全部可用 bank+recent 只剩 176–214 秒，176 个较早帧已被删。BT 两种方法均错的 146 条中，108 条有淘汰，87 条失去超过一半前缀的时间覆盖。缺少目标事件的人工时间定位，尚不能证明这些题的正确证据恰好被删；但上述容量/年龄调度冲突是实际实现行为。

这项观察与本轮读取预算问题独立，保留供后续研究；不据此修改 writer、容量或淘汰策略。REC 新增退化的历史均仍在缓存里，不能用存储问题解释这些损失。

## 4. 更好的 gate 仍不能解决全部计数与感知错误

REC 的 698 条都没有 eviction；427 条两版均错。其中 42 条在读取非空的整个历史 bank 后仍错，另有 66 条 bank 本来为空。例 `ovo-3021` 已读取 82 帧历史+16 帧 recent，覆盖 0–97 秒，答案仍为 2，标注为 9；`ovo-2616` 读取 80+16 帧，答案为 2，标注为 3。

这些记录不足以区分 1 fps 漏掉完整动作、空间池化丢细节、动作识别错误或计数推理错误。需要有针对性的片段回放和改变单个因素的实验，不能把这些错误一律归因于早停。

当前候选选择是端点优先、逐步补齐时间间隙，问题不参与帧的语义排序。因此现在是自适应“读多少”，还没有实现自适应“读哪些片段”。

## 5. 剩余 RT 差距必须有同配置 Recent16 对照

官方 Recent16 对、v3 错共有 34 题，其中 13 题 v3 没有读取任何历史；这 34 题的 recent 时间戳均与官方不同。反向 v3 对、官方错有 15 题。这表明剩余差距无法全部归因于历史干扰；需要同采样、同最终提示词、同特征路径的 recent-only 控制，才能明确剩余的 memory 净影响。

## 建议的下一版与验证顺序

1. **问题条件化预算路由。** 冻结模型根据用户问题与 Recent16 的视觉证据，直接预测 `0 / 1024 / 4096 / 16384` 历史视觉 token 预算。代码不读取 BT/RT/FT 标签、不按关键词硬分流；当前状态、跨时间关系和累计事件的差异由模型判断。路由输出只用于控制读取量，不生成或保存 caption memory。
2. **将历史需求与回答意愿分开。** 原生 Response 可作为辅助信号，不再独自决定是否读取历史。重点验证模型能否为当前状态问题选择较低预算，并避免对实际需要历史的问题过早给出零预算。上述能力是待验证假设，不能由本轮错误分析直接宣称成立。
3. **只改变读取预算，固定其他条件。** 保持 writer、容量、池化、Recent16 采样、历史候选排序和最终答题提示词相同。补同配置 recent-only 对照，与 fill、v3 及拟议预算路由配对比较。先衡量 RT 少读历史的收益和 BT/FT 错误零预算造成的损失，再考虑更复杂的片段选择。

当前预算路由尚未实现。现有四个分析脚本只分析保存的预测，不修改模型或读取器。当前全量结果已用于提出修改，后续在同一数据上改进属于开发性对比；不要把事后挑选阈值或真值 oracle 作为真实系统性能。

## 审计与文件

3035 对输入字段匹配，6070 次当前仓库评测 scorer 重评分与保存结果一致；两次运行源码与各自记录哈希匹配。最终答题 `build_chat` 与 `answer` 的 AST 相同。3035 对 bank 和 recent 元数据完全相同；1365 对最终证据元数据一致，预测也全部一致。特征张量未保存，因此不声称已验证 tensor 位级相等。此次只做分析，没有更改核心实现或启动 GPU 实验。

- `paired_analysis.py`、`paired.json`、`paired_samples.csv`：主配对审计、各子任务/停止阶段/预算统计。
- `state_signal.py/json/md`：状态概率与证据需求错配、固定阈值端点替换诊断。
- `memory_audit.py/json/md`：历史保留范围、池化/淘汰顺序及相关代码位置。
- `case_analysis.py/json`：REC 错误方向、具体案例、官方 Recent16 差距分解。chunk 路径不能恢复原始长视频轨迹，未据此声称验证了累计计数的单调性。
